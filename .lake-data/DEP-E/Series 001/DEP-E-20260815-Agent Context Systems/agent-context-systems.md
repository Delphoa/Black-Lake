## Detailed Summary

### Problem context

The source package groups signals around agents that can operate over longer horizons, larger contexts, richer tools, and more specialized domains. Those capabilities increase the surface area for hidden state, stale or irrelevant memory, prompt injection, runtime cost, evaluator gaming, data mismatch, and physical-world leakage. The package is therefore best read as a research landscape for evidence-bearing context systems rather than as a single-model comparison.

### Defensive cyber agents and open frontier scale

Google DeepMind describes Gemini 3.5 Flash Cyber as a lightweight model fine-tuned to find, validate, and patch vulnerabilities, deployed through a limited-access CodeMender pilot for governments and trusted partners. The page reports repeated invocations for wider code-path search, competitive source-reported benchmark results, and 55 unique confirmed V8 issues in one fixed-invocation comparison. These results are vendor-reported and dual-use; this artifact records the deployment boundary and evaluation framing without reproducing exploit procedures.

Kimi K3 describes a 2.8-trillion-parameter mixture-of-experts model with 104 billion activated parameters, native vision, and a one-million-token context window. The v2 HTML describes hybrid Kimi Delta Attention, Attention Residuals, Stable LatentMoE with 16 of 896 routed experts active per token, long-horizon reinforcement-learning environments, persistent rollout state, external KV retention, and deployment-aware serving. The paper reports approximately 2.5x scaling-efficiency improvement over Kimi K2 and frontier-level performance relative to the models evaluated in its suite; these are source claims tied to the paper's own configuration.

### Clinically aligned multimodal evaluation

ClinFusion proposes a cascaded vision-centric architecture for heterogeneous 2D and native 3D medical images. Its evaluation framework adds MedIF-Bench for clinically relevant instruction following and a region-of-interest-grounded report-generation metric. The paper reports outperforming leading open medical MLLMs on 20 of 24 benchmarks and comparing favorably with proprietary models on 13 of 16 multimodal benchmarks. It also describes a blinded evaluation by six board-certified radiologists over 300 CT and X-ray cases. The practical lesson is that format compliance, region-level factualness, and expert judgment can expose failure modes hidden by global text-match metrics; the result is not a clinical deployment endorsement.

### Taint confinement and independent acceptance

APPA addresses a tension in dynamic information-flow control: reading unvetted data can permanently taint an agent context and reduce utility. The proposed engine-managed branch lets a child trajectory inspect restricted material, absorb the label change locally, and return only a bounded sanitized derivative. Its benchmark compares APPA, no-fork, open, Fides, and Fides-open arms across four models, with declarative end-state predicates rather than an LLM judge. The paper reports attack-success reductions from 31%–50% open baselines to 0%–7% under APPA, while branching recovers utility on three of four models. The source also describes residual breaches and a bounded trusted-computing-base scope, so the result is a design pattern rather than a universal security guarantee.

SEAL studies a related control problem for agents that rewrite policies and the tests used to accept those edits. The paper calls the failure the verifier–deployment gap: self-authored scores can remain high while a sealed deployment measure degrades. SEAL keeps an external harness-side audit hidden from the agent, returns one accept/reject bit, and retains the incumbent after clear regression. This gives a general governance principle for autonomous updates: the object being optimized should not own the only acceptance signal.

### Long-context serving, memory, and cache compression

KAP defines a Knowledge Selection–Runtime Consumption gap: structured evidence, graph topology, multimodal alignment, and confidence signals become a flat token sequence before serving, forcing dense KV consumption. GraphSpec compiles those signals into a runtime access plan while preserving the logical prompt and verifies with the full context. In the reported Qwen3-VL-32B, vLLM, four-A800 setup over SPIQA, GraphSpec reaches 5.5% active KV/source at 128K and 1.19x decode-throughput speedup while maintaining comparable answer-level results. The paper explicitly notes that its cost model is not an exact sampling guarantee; the gains depend on the phase boundary and workload.

InMind evaluates a different bottleneck: stored facts can be directly retrievable yet unavailable when an indirect query needs them. Its 125-task expert-verified benchmark places the injected memory inside a 47-session trace, then waits through 38 further sessions before direct and indirect queries. The paper reports 84.0% for an in-context backbone with the decisive memory visible, while six retrieval or agentic memory systems reach at most 14.4% application performance despite on-demand recall up to 100%. The source interpretation is that the missing capability is query-conditioned routing or persistent visibility, not merely storage or embedding quality.

DynaCalKV separates key and value compression. It dynamically groups key-cache heads by CKA similarity and allocates rank under a parameter budget, while using offline calibration for values. Across three instruction-tuned models, the authors report competitive accuracy and caution that the method is more effective for standard multi-head attention than for grouped-query attention in long-context settings. This is a useful boundary condition: a cache optimization should be conditioned on architecture rather than promoted as a model-agnostic reduction.

### Embodied data and quantum implementation leakage

The Data Pyramid survey organizes embodied manipulation data into real-robot, UMI-style, egocentric/exocentric, simulation, and general vision-language sources. It frames the design space around scalability versus robot alignment and further considers quality, diversity, reusability, and physical fidelity. The survey highlights failure and recovery data, cross-embodiment alignment, multimodal standardization, and scalable real-world collection as unresolved issues. It is a taxonomy and synthesis, not independent proof that any recipe transfers to a physical robot.

The quantum-network paper studies whether passive observations of a fraction of an optical signal can identify protocol families without measuring encoded quantum states. Its abstract describes four protocols, detection statistics and optical power features, and source-reported identification accuracy up to 96% under one sampling configuration and 70%–89% under another. Because the full HTML page was inaccessible, this artifact treats the finding as an abstract-level locator and does not infer details about calibration, sample size, hardware, or defenses.

## Observations

- `Observed pattern`: As context windows and tool surfaces grow, the main bottleneck shifts from storing more information to deciding what is visible, trusted, executable, and retained. KAP, InMind, APPA, and SEAL each place a boundary around that decision.
- `Technical implication`: A useful context control plane likely needs both semantic selection and enforceable state labels. Retrieval relevance without a trust boundary can surface unsafe content; taint control without a bounded derivative can destroy utility; serving optimization without verification can preserve tokens but not answer quality.
- `Observed pattern`: Evaluation quality improves when the unit of analysis includes workflow state or domain conditions. ClinFusion's instruction and region-grounded measures, the InMind indirect-query split, the embodied-data dimensions, and the quantum physical-layer threat model all challenge aggregate scores that ignore the environment in which a result matters.
- `Contradiction or tension`: Longer context, persistent memory, and external tools expand capability while increasing stale-state, privacy, evaluation, and cost risks. The source set does not provide a single architecture that resolves all four simultaneously.
- `Reviewer hypothesis`: A portable evidence envelope should record source identity, context visibility, trust label, transformation or sanitizer, evaluator boundary, domain conditions, and failure trace. This is a design inference, not a schema proposed by any one source.
- `Open question`: Whether a common evidence envelope can preserve domain-specific semantics for clinical imaging, physical robotics, quantum hardware, and software agents without collapsing meaningful differences into one readiness score remains unresolved.

## Potential Implementations

### 1. Evidence-bound context router

- `User`: Security-conscious agent platform engineers.
- `Goal`: Select useful context while preserving trust, privacy, and provenance boundaries.
- `Core mechanism`: Combine KAP-style runtime access plans with APPA-style labels, child branches for untrusted reads, bounded sanitized derivatives, and an append-only event receipt.
- `Required inputs`: Synthetic or authorized documents, source labels, retrieval scores, policy rules, evaluator configuration, and a full-context fallback.
- `Outputs`: Selected context view, trust and provenance receipt, policy decision, fallback reason, and redacted failure trace.
- `Risk controls`: Local-only test data, deny-by-default egress, explicit human approval for sensitive release, immutable audit identifiers, and no raw secret logging.
- `Evaluation`: Measure utility, leakage, stale-state handling, false blocks, latency, and recovery under synthetic adversarial fixtures.

### 2. Long-context evidence replay harness

- `User`: ML systems and inference engineers.
- `Goal`: Test whether context selection reduces physical KV work without changing answer quality.
- `Core mechanism`: Recreate KAP's full-context verification and selected-KV view over public or synthetic documents, with architecture-specific cache baselines inspired by DynaCalKV.
- `Required inputs`: Public text or synthetic evidence, fixed model and tokenizer, context-length sweep, cache metrics, and answer-level evaluator.
- `Outputs`: Quality, latency, active-KV, memory, fallback, and uncertainty report.
- `Risk controls`: No private corpus, no hidden user prompts, full-context fallback, version pins, and bounded resource budgets.
- `Evaluation`: Compare full context, selected context, compressed cache, and failure fallback across 4K–128K-like nested workloads where feasible.

### 3. Workflow and verifier boundary registry

- `User`: Evaluation and governance teams operating autonomous research agents.
- `Goal`: Prevent self-authored tests or aggregate scores from becoming the sole deployment gate.
- `Core mechanism`: Record workflow stage, authoritative state, evaluator ownership, hidden-holdout status, accept/reject decision, rollback, and unresolved evidence.
- `Required inputs`: Synthetic task traces, external checker, stage taxonomy, evaluator version, and retention policy.
- `Outputs`: Stage-aware readiness report, verifier–deployment gap, failure taxonomy, and next-review queue.
- `Risk controls`: Independent checker ownership, no agent access to hidden test content, bounded feedback, human override, and audit-log minimization.
- `Evaluation`: Compare self-authored and external acceptance under distribution shift, regression injection, stale state, and evaluator disagreement.

### 4. Domain-grounded multimodal review bench

- `User`: Research groups evaluating medical, embodied, or other specialized multimodal agents.
- `Goal`: Measure domain-relevant factualness, instruction following, physical alignment, and failure recovery.
- `Core mechanism`: Combine ClinFusion-style region or format checks with Data Pyramid-style provenance dimensions and expert-reviewed edge cases.
- `Required inputs`: Public or synthetic domain records, task instructions, modality metadata, expert rubric, and safe simulator where physical action is involved.
- `Outputs`: Subgroup/domain scorecard, evaluator agreement, provenance record, and deployment blockers.
- `Risk controls`: De-identification, consent and license review, non-diagnostic framing, simulator-first testing, and human sign-off.
- `Evaluation`: Compare aggregate metrics with domain-grounded metrics and report discrepancies rather than selecting the favorable score.

## Three Ways to Exercise This Research

1. **Synthetic taint-and-routing exercise**: Objective—test whether a context router can preserve utility while preventing a synthetic confidential field from reaching an unauthorized sink. Inputs—dummy records, public-safe policy labels, and fixed prompts. Method—run full-context, taint-only, branch-and-sanitize, and deny-by-default variants; record utility, blocked flows, and receipts. Output—a small evidence-envelope dataset. Success criterion—no unauthorized release with a documented utility tradeoff. Safety boundary—synthetic data only; stop if any real credential, personal record, or external side effect is introduced.
2. **Long-context serving replay**: Objective—test the relationship between context length, selected-KV access, cache compression, answer quality, and fallback behavior. Inputs—public-domain documents or generated text, a fixed local model if available, and nested 4K–128K-like prompts. Method—compare full-context, selected-context, and architecture-aware cache variants under a fixed budget. Output—a quality/latency/memory table with failure cases. Success criterion—any claimed efficiency gain must preserve the declared answer-quality threshold and include a full-context fallback. Safety boundary—no private corpus or production traffic; stop on missing version or evaluator controls.
3. **Verifier-boundary tabletop**: Objective—exercise the SEAL principle without autonomous code modification. Inputs—synthetic candidate policies, visible self-tests, hidden evaluator cases, and a fixed accept/reject gate. Method—inject regressions that pass visible tests, compare self-authored acceptance with hidden evaluation, and record rollback decisions. Output—a verifier–deployment gap report and governance checklist. Success criterion—the external gate rejects every declared regression and preserves the incumbent. Safety boundary—offline simulation only; no self-modifying agent or live deployment.

## Example MVP Product

- `Product name`: Context Gate
- `Target user`: Teams building tool-using or research agents that need auditable context and evaluation boundaries.
- `Problem`: Agents can retrieve irrelevant or sensitive facts, spend excessive serving resources, and accept changes using tests that do not represent deployment behavior.
- `Core workflow`: Ingest a public or authorized document with provenance and trust labels; build a structured evidence graph; compile a selected-context plan; quarantine untrusted reads in a child view; run a bounded task; verify with an external checker; and emit a receipt containing selected evidence, policy decisions, evaluator identity, and fallback state.
- `Data requirements`: Public or synthetic documents, repository-relative source identifiers, policy labels, task traces, evaluator versions, and non-sensitive performance counters. No raw secrets, patient records, or restricted datasets in the MVP.
- `Architecture`: Local-first ingestion and label store; deterministic policy and provenance layer; optional retrieval/graph planner; model adapter with full-context fallback; hidden or separately owned evaluator; append-only redacted receipts; review dashboard.
- `Success metrics`: Unauthorized-release rate, false-block rate, answer quality relative to full context, active-KV or memory reduction, p95 latency, verifier–deployment gap, receipt completeness, and human review agreement.
- `Risk controls`: Deny-by-default sensitive egress, synthetic fixtures, local processing, human approval for external actions, evaluator isolation, immutable version pins, retention limits, and explicit fail-open/fail-closed policy.
- `Limitations`: The MVP cannot prove general security, clinical correctness, physical-world safety, or quantum-network privacy. It depends on correct labels, trusted evaluators, compatible model adapters, and domain-specific calibration.
- `MVP boundary`: No autonomous exploit generation, clinical diagnosis, physical robot control, or live self-modifying deployment.
- `Deployment model`: Local CLI and browser review surface with optional isolated batch evaluation.
- `Evaluation plan`: Synthetic policy tests, public-document replay, regression-injection tests, evaluator disagreement review, and one independently reproduced source mechanism before any broader claim.
- `Failure modes`: Missing provenance, stale labels, evaluator drift, false quarantine, hidden data leakage through metadata, cache-quality regression, and a misleading readiness score from incomplete domain coverage.
- `Maintenance plan`: Versioned source registry, evaluator calibration reviews, dependency pinning, correction notes, receipt schema migrations, and periodic human audit of retention and privacy controls.
